Carpeta, proyecto, intérprete y entorno

Cuatro palabras casi iguales, y cómo se ve cada una en VS Code.

⭐ Lo esencial
  • En un proyecto normal, carpeta de trabajo, proyecto y entorno son lo mismo: una carpeta, con el entorno (.venv) dentro.
  • El intérprete es el programa python de ese entorno. VS Code lo elige solo y te lo dice abajo a la derecha.
  • Si algo «no encuentra» una librería, casi siempre es que VS Code usa otro intérprete. Se arregla en dos clics.

1. Cuatro palabras que parecen lo mismo

Al empezar se mezclan cuatro ideas. Es normal: en la práctica viven juntas. Pero conviene distinguirlas, porque los mensajes de error y los menús de VS Code las usan por separado.

IdeaQué esDónde lo ves
Carpeta de trabajoLa carpeta que has abierto en VS Code.Arriba del Explorador, con el nombre en mayúsculas.
ProyectoEsa carpeta, cuando tiene pyproject.toml y estructura (src/, tests/). VS Code no tiene un «proyecto» como tal: es una idea tuya y de uv.El archivo pyproject.toml en la raíz.
Entorno virtualLa carpeta .venv con Python y librerías propias.En el Explorador, como .venv.
IntérpreteEl programa python concreto con el que se ejecuta tu código. Cada entorno tiene el suyo.Barra de estado, abajo a la derecha.

2. Cómo sabe VS Code qué Python usar

Cuando abres una carpeta con Python, la extensión busca un intérprete por este orden:

  1. Si el proyecto lo indica en .vscode/settings.json (la línea python.defaultInterpreterPath), usa ese. Nuestro proyecto lo hace: apunta a .venv/bin/python.
  2. Si no, busca entornos dentro de la carpeta, como .venv, y suele elegir ese.
  3. Si no encuentra nada, usa el Python del sistema.

Dónde mirar qué ha elegido: la barra de estado, la franja de abajo de la ventana, a la derecha. Verás algo como 3.13.18 (.venv). El texto exacto cambia un poco entre versiones, pero siempre aparece el número de Python y el nombre del entorno.

🧪 Pruébalo tú
  1. Abre la carpeta de un proyecto con .venv y un archivo .py.
  2. Mira abajo a la derecha: ¿qué Python dice? ¿Aparece .venv?
  3. Abre una terminal nueva (Terminal → Nueva terminal) y comprueba que el prompt empieza con (.venv).
  4. Escribe which python (en Windows, where python) y comprueba que apunta a una ruta que termina en .venv/bin/python.

3. El prompt: cómo «suele» marcarse el entorno activo

Cuando un entorno está activo en una terminal, lo habitual es que el prompt (el texto que aparece antes de lo que escribes) lleve su nombre entre paréntesis:

ana@equipo:~/mi-proyecto$ which python
# ninguno activo: Python del sistema o nada
ana@equipo:~/mi-proyecto$ source .venv/bin/activate
(.venv) ana@equipo:~/mi-proyecto$ which python
/home/ana/mi-proyecto/.venv/bin/python

Esa es la señal que ya viste en el paso 1. Pero fíjate: tú no has escrito source …/activate. Lo hace la extensión Python por ti, escribiendo ese comando en la terminal como si lo tecleases. Lo habitual es que ocurra:

  • al abrir una terminal nueva dentro de VS Code, si ya hay un intérprete elegido;
  • y, según tu versión, cuando la extensión se pone en marcha, lo que pasa al abrir o seleccionar un archivo .py. Por eso a veces ves aparecer (.venv) «de repente» en una terminal que ya estaba abierta.

Si no quieres ese comportamiento, la opción se llama python.terminal.activateEnvironment (se desactiva poniéndola en false) y, en las versiones nuevas, python-envs.terminal.autoActivationType. Con uv no es necesario activar nada para ejecutar tu programa (paso 6), pero sí ayuda a que pytest, ruff y python sueltos usen el entorno del proyecto.

Y con el entorno activo, las herramientas son las del entorno

Esto explica el comportamiento que parecía magia. Con el entorno activo, pytest, ruff o pip se buscan primero en .venv/bin (recuerda el orden del PATH del paso 1). Por eso ejecutan la versión instalada en este proyecto, y no otra.

4. Cambiar de entorno

Desde VS Code (a mano)

  1. Haz clic en el intérprete de la barra de estado, o pulsa Ctrl+Mayús+P y escribe Python: Select Interpreter.
  2. Elige un intérprete de la lista. Los entornos del proyecto aparecen con su nombre (.venv).
  3. Si el que buscas no sale, elige Enter interpreter path… y apunta a su python.
  4. Abre una terminal nueva para que se active el nuevo.

Con uv (el camino cómodo)

Con uv casi nunca cambias de entorno a mano, porque cada proyecto tiene uno solo. Lo que sí puedes cambiar es qué versión de Python usa:

$ cat .python-version
3.13
$ uv python list --only-installed
# muestra los Python que uv encuentra en tu equipo

El archivo .python-version dice la versión que quiere el proyecto, y pyproject.toml dice cuál es la mínima (requires-python). Para cambiarla, uv python pin 3.12 actualiza ese archivo, y uv sync reconstruye el entorno con ella. Si pyproject.toml pide una versión más alta, uv te lo dice con un error.

⚠️ Ojo: el síntoma típico Si en el editor ves el subrayado «Import "requests" could not be resolved», pero en la terminal con uv run el programa funciona, VS Code está usando otro intérprete (probablemente el del sistema). Mira la barra de estado y elige el de .venv.

❓ Compruébalo

¿Puedo tener dos entornos en la misma carpeta?

Técnicamente sí, pero con uv no tiene sentido: cada proyecto tiene uno, el .venv. Si necesitas probar otra versión de Python, cambia la versión del proyecto, o crea otra carpeta de proyecto.

Abrí una terminal nueva y no sale (.venv). ¿Por qué?

Probablemente VS Code no tiene elegido el intérprete del proyecto, o el entorno aún no existe (ejecuta uv sync). Elige el intérprete en la barra de estado y abre otra terminal. Si sigue sin salir, comprueba que la opción python.terminal.activateEnvironment no esté desactivada.

¿Hace falta activar el entorno para usar uv?

No. uv run usa el entorno del proyecto sin que lo actives. Lo verás en el paso 6.
