pyproject.toml por dentro

La ficha de tu proyecto, sección por sección.

⭐ Lo esencial
  • pyproject.toml es un archivo de texto con la ficha de tu proyecto: nombre, versión de Python, librerías, cómo arrancarlo y cómo se comportan Ruff y pytest.
  • Está dividido en secciones entre corchetes. Cada herramienta lee solo la suya.
  • Casi todo lo rellena uv. Tú lo lees, y de vez en cuando cambias algo pequeño.

1. Qué es TOML

TOML es un formato de texto pensado para configurar cosas. Tiene tres ideas y ya lo sabes leer:

# Esto es un comentario
[seccion]                 # un título entre corchetes
clave = "valor"           # texto entre comillas
numero = 88               # un número, sin comillas
lista = ["a", "b"]        # una lista entre corchetes

Lo de pyproject es porque el archivo es «el proyecto de Python» (py + project), y .toml porque está escrito en TOML.

2. Recorrido por un archivo real

Este es el pyproject.toml de un proyecto creado con /python-pro:init y con requests añadido. Cada color es una sección y debajo verás qué hace:

Sección por sección

SecciónQué dice
[project]La ficha. name es el nombre del paquete; requires-python = ">=3.13" dice que hace falta Python 3.13 o superior (si alguien intenta usar uno más antiguo, uv avisa); dependencies son las librerías que tu programa necesita para funcionar. El >=2.34.2 significa «esa versión o una posterior».
[project.scripts]Los comandos de tu programa. start = "mi_proyecto:main" crea el comando start, que ejecuta la función main del paquete mi_proyecto. Lo ves en acción en el paso 6.
[build-system]Quién empaqueta tu código para que quede instalado en el entorno. uv trae el suyo (uv_build). Puedes ignorarla.
[dependency-groups]Grupos de librerías. El grupo dev son las de desarrollo: pytest y ruff. Se añaden con uv add --dev.
[tool.ruff]Los ajustes de Ruff. line-length = 88 es el ancho máximo de línea, y select es la lista de familias de revisiones que quieres (E/F errores típicos, I orden de importaciones, UP modernizar código, B fallos probables).
[tool.pytest.ini_options]Los ajustes de pytest. testpaths = ["tests"] dice que las pruebas están en la carpeta tests.
💡 Fíjate en el patrón [tool.algo] Cualquier herramienta puede guardar su configuración aquí, en una sección [tool.su-nombre]. Antes cada herramienta tenía su archivo (.flake8, pytest.ini, setup.cfg…). Ahora, uno solo.

3. Para qué sirve todo junto

  • Reproducir el proyecto en otro sistema. En otro ordenador, uv sync lee requires-python, dependencies y el grupo dev, y monta el mismo entorno (paso 4).
  • Que todos usen las mismas reglas. Ruff y pytest leen la configuración del propio proyecto, así que te dan el mismo resultado en cualquier equipo.
  • Que el comando de arranque sea el mismo. uv run start funciona igual para ti, para tu compañero y para cualquier sistema automático que ejecute el proyecto.
  • Saber de un vistazo qué necesita tu proyecto. Es la primera cosa que abre alguien que no conoce el código.
🧪 Pruébalo tú: cambia algo pequeño
  1. Abre pyproject.toml y cambia line-length = 88 por line-length = 60.
  2. En la terminal: uv run ruff check. Si hay líneas largas, Ruff las marcará.
  3. Vuelve a poner 88. Has cambiado el comportamiento de una herramienta tocando solo una línea de texto.
⚠️ Ojo Si cambias una sección de librerías a mano, pide a uv que ponga al día el entorno con uv sync. Y no edites nunca el uv.lock: lo escribe uv.

❓ Compruébalo

¿Qué significa requests>=2.34.2 frente a requests==2.34.2?

>= admite esa versión o una más moderna; == exige exactamente esa. Para ver la exacta que se instaló, mira el uv.lock, no el pyproject.toml.

¿Por qué hay dos sitios con pytest y ruff (en dev y en [tool…])?

Son cosas distintas: en [dependency-groups] dices que quieres instalar esas herramientas, y en [tool.ruff] o [tool.pytest…] dices cómo deben comportarse.

¿Dónde está el nombre de la carpeta con mi código?

El nombre del paquete es mi-proyecto en [project], pero la carpeta se llama mi_proyecto (con guion bajo), porque Python no admite guiones en nombres de módulos. Está dentro de src/.
