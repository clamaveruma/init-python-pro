Git y GitHub

Guardar el historial, volver atrás y compartir.

⭐ Lo esencial
  • Git guarda el historial de tu proyecto en tu ordenador: cada «commit» es una foto con una nota. Puedes volver a cualquiera.
  • GitHub es una web donde guardas una copia de ese historial, para tener una copia de seguridad y compartirlo.
  • No se guarda todo: el entorno .venv y los archivos temporales se quedan fuera a propósito.

1. Para qué sirve Git

Seguro que has tenido script_final.py, script_final_v2.py y script_final_AHORA_SI.py. Git sustituye eso por una sola carpeta y un historial: cada vez que algo funciona, haces una «foto» (un commit) con una frase que explica qué cambió. Si algo se rompe, ves qué cambió y puedes volver atrás.

💡 ¿Y si no tengo Git? VS Code no trae Git: solo lo usa si lo encuentra instalado. Compruébalo con git --version. Si no sale un número de versión, instálalo (en Linux, sudo apt install git; en macOS, xcode-select --install; en Windows, desde git-scm.com) y dile quién eres una vez: git config --global user.name "Tu Nombre" y git config --global user.email "tu@correo".

2. Las tres zonas

Lo que más confunde al principio es que Git tiene tres sitios por los que pasa tu trabajo. Con una analogía: preparar un álbum de fotos.

🧪 Pruébalo tú Abre una terminal en tu proyecto y sigue la vida de un cambio. Los resultados son de un proyecto de prueba; tus códigos de commit serán distintos. 
$ git status
nothing to commit, working tree clean
# ... editas un archivo ...
$ git status --short
 M README.md                  # modificado, sin preparar
$ git add README.md
$ git status --short
M  README.md                  # preparado para la foto
$ git commit -m "docs: explain how to run"
$ git log --oneline
a3c9e10 docs: explain how to run
f416792 feat(taxes): add VAT calculation
2fb119e chore: initial project scaffold

3. Qué se guarda y qué no

Git guarda tu código y su receta. No guarda lo que se puede volver a generar. Para eso está el archivo .gitignore, con la lista de lo que Git debe ignorar. El de nuestro proyecto incluye:

# .gitignore (fragmento)
__pycache__/            # archivos temporales de Python
.venv                   # el entorno virtual
.claude/dev-journal.md  # tus notas personales de trabajo
🧪 Pruébalo tú 
$ git check-ignore -v .venv
.gitignore:10:.venv    .venv
Esa línea dice «.venv está ignorado por la línea 10 de .gitignore». Si alguna vez un archivo no aparece en git status, esta orden te dice por qué.

4. Los mensajes de commit

Cada foto lleva una frase. Una buena costumbre son los Conventional Commits: empezar con una etiqueta que diga de qué tipo es el cambio. Es lo que sigue Claude en estos proyectos.

EtiquetaCuándoEjemplo
featUna función nuevafeat(taxes): add VAT calculation
fixUn arreglofix(taxes): round to two decimals

5. Git en VS Code

No tienes que memorizar los comandos. El tercer icono de la barra lateral (un nudo de ramas) es Control de código fuente:

  • Muestra la lista de archivos cambiados. Si pulsas uno, ves lado a lado qué cambió.
  • El + junto a un archivo hace git add.
  • Escribes la frase en la caja de arriba y pulsas Confirmar (Commit).
  • El botón Sincronizar cambios hace push y pull.

Con Claude no hace falta ni eso: sus reglas le piden hacer commit al terminar cada tarea verificada (paso 8).

6. GitHub

GitHub no es Git: es un servicio web que guarda tu repositorio en internet. Para subir tu proyecto necesitas dos cosas: una cuenta en github.com y que tu ordenador se identifique. Lo más cómodo es la herramienta oficial gh:

$ gh auth login          # una vez: te guía para iniciar sesión
$ gh repo create mi-proyecto --private --source=. --remote=origin --push

La segunda orden crea el repositorio en GitHub, lo conecta con tu carpeta y sube el historial. Es lo que hace /python-pro:init si le dices que quieres GitHub. Desde ese momento, git push sube los commits nuevos y, en otro ordenador, git clone + uv sync (paso 4) te devuelve el proyecto funcionando.

⚠️ Ojo: «privado» o «público» En un repositorio público cualquiera puede ver todo el código y su historial, incluso lo que borraste después. No subas contraseñas, claves ni datos personales: ni en el código ni en ningún archivo. Si dudas, elige privado; siempre puedes hacerlo público más tarde.

❓ Compruébalo

¿Hace falta GitHub para usar Git?

No. Git funciona solo en tu ordenador. GitHub añade la copia en internet. Por eso /python-pro:init te pregunta si quieres GitHub o no.

Hice un cambio y me arrepiento. ¿Puedo deshacerlo?

Si aún no hiciste commit, git restore archivo devuelve el archivo a como estaba en el último commit. Ten cuidado: lo que cambiaste se pierde. Si ya hiciste commit, puedes volver al estado anterior con Claude o con git revert.

¿Por qué Claude hace commit solo pero no hace git push?

Un commit se queda en tu ordenador y se puede corregir. Un push publica el cambio fuera, así que por defecto Claude solo lo hace si se lo pides, a menos que al crear el proyecto le hayas dicho que sí de forma explícita.
