Cómo arrancar tu programa

uv run, python3, el script directo y F5: qué hace cada uno.

⭐ Lo esencial
  • Un proyecto define un punto de entrada: la función por la que empieza. Nuestro comando es start, que arranca mi_proyecto:main.
  • uv run start asegura primero que el entorno está al día y después ejecuta tu programa con el Python del entorno.
  • python3 archivo.py y los scripts con shebang usan el Python que encuentren primero. Si no es el del proyecto, fallan o, peor, usan librerías de otro sitio.

1. El punto de entrada

Un programa necesita saber por dónde empezar. En nuestro proyecto es la función main del paquete mi_proyecto:

# src/mi_proyecto/__init__.py
def main() -> None:
    print("Hello from mi-proyecto!")

# src/mi_proyecto/__main__.py
from mi_proyecto import main

main()

# pyproject.toml
[project.scripts]
start = "mi_proyecto:main"

Dicho de otro modo: start = "mi_proyecto:main" significa «el comando start es la función main que está dentro de mi_proyecto». Y el archivo __main__.py sirve para que también se pueda arrancar con python -m mi_proyecto.

2. Cinco formas de arrancar, una al lado de otra

Partimos de la misma carpeta, con el mismo proyecto. Estas son las formas habituales y lo que pasa con cada una.

A. uv run start

$ uv run start
Hello from mi-proyecto!

Funciona siempre, desde una terminal sin ningún entorno activo.

B. python3 -m mi_proyecto, sin entorno

$ python3 -m mi_proyecto
/usr/local/bin/python3: No module named mi_proyecto

El python3 del sistema no sabe que tu proyecto existe: no está instalado en su carpeta de librerías, sino en la de .venv. Si usas el de .venv, sí funciona:

$ .venv/bin/python -m mi_proyecto
Hello from mi-proyecto!

O con el entorno activo (source .venv/bin/activate), porque entonces python es el de .venv.

C. El script directo, con shebang

La primera línea de un script puede empezar con #!, el shebang: le dice al sistema con qué programa ejecutarlo. Lo normal es #!/usr/bin/env python3, que significa «busca python3 en el PATH». Un ejemplo, el archivo hola.py:

#!/usr/bin/env python3
import sys
print(sys.executable)

$ chmod +x hola.py
$ ./hola.py
/usr/local/bin/python3        # el Python del sistema
$ uv run hola.py
/…/mi-proyecto/.venv/bin/python3   # el del entorno del proyecto

El mismo archivo, dos Python distintos. Con el shebang obtienes el primero que encuentre el PATH, y eso depende de lo que tenga activado cada persona en su terminal.

D. F5 en VS Code

El botón de ejecutar y depurar usa el intérprete que tienes elegido abajo a la derecha (paso 3) y el archivo .vscode/launch.json, que dice: "module": "mi_proyecto". Es equivalente a la forma B con el entorno correcto, más la posibilidad de poner puntos de parada.

E. Un script suelto con uv run archivo.py

Sirve también para pruebas rápidas: uv run archivo.py ejecuta el archivo con el Python del entorno del proyecto.

💡 Entonces, ¿cuál uso? Para uso diario y para compartir, uv run start. Para depurar, F5. Los demás conviene conocerlos para entender qué pasa cuando alguien te dice «a mí me falla con python3…».
🧪 Pruébalo tú
  1. En una terminal sin entorno activo, ejecuta python3 -m mi_proyecto. Verás el error.
  2. Ejecuta ahora uv run start. Funciona.
  3. Ejecuta source .venv/bin/activate y luego python -m mi_proyecto. También funciona: acabas de recrear a mano lo que hace uv run.

❓ Compruébalo

¿Por qué uv run a veces dice «Building…» o «Installed 1 package»?

Porque ha detectado que algo ha cambiado (por ejemplo, tu proyecto) y ha puesto al día el entorno antes de arrancar. Si no hay cambios, no sale nada.

¿Existe un shebang que use uv?

Sí, para scripts sueltos: #!/usr/bin/env -S uv run --script más un comentario especial con sus librerías. Es una función de uv para scripts de un solo archivo, y queda fuera de esta guía, que trata de proyectos.

Mi compañero ejecuta con python3 y funciona. ¿Entonces no hace falta uv run?

Le funciona porque en su equipo hay, por casualidad, un Python con tus librerías. Es justo lo que los entornos intentan evitar. Con uv run se garantiza que ambos usáis lo mismo.
